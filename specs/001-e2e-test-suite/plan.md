## Summary

Write 10 new Playwright spec files covering all 20 missing E2E journeys identified by `/sp.test-status`. Tests validate the existing ZADIIS store implementation — no application code changes. Three P1 critical paths (Safepay payment, OTP verification, Order confirmation) are prioritised first, followed by P2 (Analytics, Payments, Returns) and P3 (Sales, Settings+Shipping, Inventory, Invoices).

See `research.md`. Key decisions:

1. **Order confirmation route** is `/order/[id]` (UUID), NOT `/order-confirmation` — spec updated
2. **OTP testing**: mock `/api/otp/send` with `page.route()` to return a known 6-digit code; test modal UI with that code
3. **Safepay testing**: intercept `POST /api/payments/tracker` to capture redirect URL; call webhook directly for paid-state tests; skip if `SAFEPAY_SECRET_KEY` absent
4. **No `/admin/categories`** or `/admin/customers`** pages exist — those stories removed
5. **Admin returns** managed within `/admin/orders` — extend existing `orders.spec.ts`
6. **Inventory** tested via product edit page — new `inventory.spec.ts` navigates to `/admin/products/[id]/edit`

## Phase 1: Implementation Phases

### Group A — P1 Store (implement first, highest revenue risk)

#### A1: `tests/store/checkout-safepay.spec.ts`

**Approach:**
- Use `page.route('**/api/payments/tracker', ...)` to capture the Safepay redirect URL from the API response
- Fill checkout form fully (name, phone, email, address, city)
- Select Safepay payment option
- Intercept the tracker API response to get the redirect URL
- Verify redirect URL matches `https://sandbox.safepay.pk/*` or similar pattern
- For paid-state test: call `POST /api/webhooks/safepay` directly via `page.request.post()` with crafted payload + HMAC signature (using `SAFEPAY_SECRET_KEY` from env)
- Skip entire file if `SAFEPAY_SECRET_KEY` not set

**Seed helper**: same `seedCartAndGoToCheckout()` as `checkout.spec.ts`

**Tests:**
1. `Safepay option is visible at checkout` — renders the radio/button
2. `selecting Safepay and submitting redirects to payment gateway` — intercept + verify URL
3. `cancelled Safepay payment does not create order` — mock tracker returns redirect, don't complete payment, verify no order in success state
4. `Safepay webhook with valid payload creates paid order` — POST to webhook directly, verify order page shows payment confirmed
5. `Safepay webhook with invalid signature returns 401` — POST without valid HMAC

---

#### A2: `tests/store/checkout-otp.spec.ts`

**Approach:**
- Use `page.route('**/api/otp/send', route => route.fulfill({ json: { success: true } }))` to prevent real email
- After intercepting send, read known OTP from Supabase `email_otps` table via `page.request.get('/api/...')` OR hardcode a test OTP by inserting via a setup fixture
- Simpler: use `page.route('**/api/otp/verify', ...)` to mock verify endpoint too — tests the UI flow fully without DB dependency

**Decision**: Mock both `/api/otp/send` (return success) and use a fixed test code `123456`. Route `/api/otp/verify` to validate `123456` as correct and any other code as wrong.

**Tests:**
1. `OTP modal appears after valid form submission`
2. `correct OTP code submits order and redirects to confirmation`
3. `wrong OTP code shows error message`
4. `resend OTP button triggers new send request`
5. `OTP rate limit error is shown when resending too quickly` (mock 429 response)

---

#### A3: `tests/store/order-confirmation.spec.ts`

**Approach:**
- Navigate to `/order/[id]` using a known order ID from Supabase (data-dependent skip if no orders)
- Alternatively, place a COD order in the test and capture the redirect URL

**Decision**: Place a COD order (reuse checkout test helper), capture redirect to `/order/[id]`, then assert on confirmation page contents.

**Tests:**
1. `COD order confirmation page shows order number` — place order, land on /order/[id], check ZD- number
2. `order confirmation shows customer name and items`
3. `order confirmation shows payment method (COD)`
4. `invalid order ID shows not-found message` — visit `/order/00000000-0000-0000-0000-000000000000`
5. `WhatsApp contact link is present`

## Risk Mitigations

| Risk | Mitigation in Plan |
|---|---|
| Safepay env vars absent | `test.skip()` if `!process.env.SAFEPAY_SECRET_KEY` |
| No orders in DB | `test.skip()` for all order-dependent assertions |
| OTP real email send | Mock both send + verify routes in OTP tests |
| Flaky admin page loads | `page.waitForSelector` on a stable element before assertions |
| Settings save side effects | Restore original value after test (afterEach) |
